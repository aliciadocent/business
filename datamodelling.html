01

Wat is een database?

Een database is een georganiseerde verzameling gegevens, zo opgeslagen dat je ze snel en betrouwbaar terugvindt, aanpast en combineert.

Je gebruikt elke dag databases zonder dat je het merkt. Spotify bewaart je playlists, de AH-app je bonuskaart en aankopen, Instagram wie wie volgt, en een game bewaart wie de hoogste score heeft. Achter al die apps draait een DBMS (database management system): software die de gegevens opslaat, bewaakt en doorzoekt. In deze werkplaats gebruik je MySQL, een van de meest gebruikte DBMS'en ter wereld.

Waarom niet gewoon Excel?

Een spreadsheet lijkt op een database: rijen en kolommen. Toch loop je met Excel snel vast zodra meer mensen of meer data meedoen.

Spreadsheet (Excel)Database (MySQL)
GebruikersEén persoon tegelijk aan het bestandDuizenden gebruikers en apps tegelijk
RegelsJe kunt overal alles typenEen score is een getal, een gebruikersnaam is uniek
VerbandenHandmatig kopiëren tussen tabbladenVastgelegd met sleutels, de database bewaakt ze
OmvangWordt traag bij honderdduizenden rijenMiljoenen rijen zonder problemen
Gebruik door appsLastigElke programmeertaal kan ermee praten

SQL en NoSQL

Er zijn twee grote families databases. SQL-databases (ook wel relationele databases) slaan gegevens op in tabellen met vaste kolommen. Je praat ermee in de taal SQL. Je spreekt het uit als "sequel" of als losse letters S-Q-L. NoSQL-databases ("not only SQL") werken zonder vaste tabellen. Vaak slaan ze documenten op in JSON-vorm.

SQL (relationeel)NoSQL
OpslagTabellen met rijen en kolommenDocumenten (JSON), sleutel-waarde, grafen
StructuurVooraf vastgelegd (schema)Flexibel, elk document mag anders zijn
VerbandenSterk: tabellen koppelen met sleutelsZwakker: gegevens staan vaak dubbel
Sterk inBetrouwbare, samenhangende data: bestellingen, betalingen, voorraadEnorme hoeveelheden losse data die snel verandert: berichten, logs, sensordata
VoorbeeldenMySQL, MariaDB, PostgreSQL, SQL ServerMongoDB, Redis, Neo4j, Cassandra

Hetzelfde gegeven ziet er in beide werelden anders uit. Zo slaat een NoSQL-database een speler met zijn scores op: alles in één document.

{
  "gebruikersnaam": "PixelPia",
  "land": "Nederland",
  "scores": [ { "score": 12450, "level": 7 }, { "score": 15890, "level": 9 } ]
}

Een SQL-database splitst dit in twee tabellen: één met gebruikers en één met scores, gekoppeld via een gebruiker_id. In hoofdstuk 5 maak je precies deze twee tabellen.

Oefenen

  1. Noem drie apps die jij gebruikt en bedenk welke gegevens ze in een database bewaren.

    Voorbeeldantwoord

    Strava: gebruikers, ritten, afstanden, routes. Netflix: accounts, profielen, wat je hebt gekeken en tot welke minuut. Een webshop: klanten, producten, bestellingen, betalingen.

  2. Een webshop bewaart bestellingen en betalingen. Kies je SQL of NoSQL? Waarom?

    Antwoord

    SQL. Een bestelling hoort bij precies één klant en bevat bestaande producten. Die verbanden moeten kloppen, en geld mag nooit "ongeveer goed" zijn. Een relationele database bewaakt dat.

  3. Waarom zou een chat-app als WhatsApp voor de berichten zelf eerder NoSQL kiezen?

    Antwoord

    Er komen elke seconde miljoenen berichten bij, met wisselende inhoud (tekst, foto, spraak). Een flexibele structuur die makkelijk over veel servers te verdelen is, past daar beter bij.

02

MySQL installeren met Docker

Je installeert MySQL niet rechtstreeks op je laptop, maar draait het in een Docker-container. Zo heeft iedereen in de klas precies dezelfde versie en instellingen.

Image en container

  • Een image is het recept: een bevroren pakket met MySQL en alles wat het nodig heeft.
  • Een container is de taart die je uit dat recept bakt: een draaiende, afgesloten kopie van het image. Gooi je de container weg, dan blijft het recept bestaan.

De container draait op jouw laptop. Er gaat niets naar internet: je database staat lokaal.

  1. Installeer Docker Desktop Download via docker.com/products/docker-desktop.
    • Windows: laat "Use WSL 2" aangevinkt. Vraagt het installatieprogramma om WSL bij te werken? Open PowerShell als administrator, typ wsl --install of wsl --update en herstart je laptop.
    • Mac: kies de versie voor jouw chip: Apple Silicon (M1 t/m M4) of Intel. Je vindt dit onder Apple-menu → Over deze Mac.
  2. Start Docker Desktop Wacht tot linksonder "Engine running" staat. Een Docker-account heb je niet nodig.
  3. Test Docker Open een terminal: PowerShell op Windows, Terminal op Mac. Zie je "Hello from Docker!"? Dan werkt het. 
    docker run hello-world
  4. Download het MySQL-image lts staat voor long-term support: de stabiele versie. 
    docker pull mysql:lts
  5. Start je MySQL-container 
    docker run --name mysql-db -e MYSQL_ROOT_PASSWORD=welkom -p 3306:3306 -d mysql:lts
    OnderdeelBetekenis
    --name mysql-dbDe naam van je container. Die gebruik je in alle volgende commando's.
    -e MYSQL_ROOT_PASSWORD=welkomHet wachtwoord van de beheerder (root). Prima voor oefenen op je eigen laptop, nooit voor een echte server.
    -p 3306:3306Verbindt poort 3306 van je laptop met de container, zodat je SQL-programma (hoofdstuk 3) erbij kan.
    -dDraai op de achtergrond.
    mysql:ltsHet image waaruit de container gemaakt wordt.
  6. Controleer of hij draait Je ziet mysql-db in de lijst. In Docker Desktop staat hij ook onder Containers. Geef MySQL na de eerste start ongeveer 20 seconden om op te starten. 
    docker ps
  7. Praat met MySQL via de terminal Typ het wachtwoord welkom. Je ziet tijdens het typen niets; dat hoort zo. De prompt wordt mysql>. 
    docker exec -it mysql-db mysql -u root -p
    SELECT VERSION();
exit

Stoppen en weer starten

Je hoeft de container maar één keer aan te maken. Daarna start en stop je hem, ook via de knoppen in Docker Desktop. Je data blijft bewaard zolang je de container niet verwijdert.

docker stop mysql-db
docker start mysql-db
Let op

docker rm mysql-db verwijdert de container én alle databases erin.

Oefenen

  1. Wat is het verschil tussen een image en een container?

    Antwoord

    Het image is het vaste pakket (het recept). Een container is een draaiende kopie daarvan (de taart). Uit één image kun je meerdere containers maken.

  2. Je klasgenoot krijgt port is already allocated. Wat is er aan de hand?

    Antwoord

    Op zijn laptop gebruikt al een ander programma poort 3306, meestal een eerder geïnstalleerde MySQL of XAMPP. Kies een andere poort aan de laptopkant: -p 3307:3306.

  3. Wat print SELECT VERSION(); bij jou?

    Antwoord

    Het versienummer van MySQL in je container, bijvoorbeeld 9.7.x. Zie je een getal, dan werkt alles.

04

SQL als taal

SQL (Structured Query Language) is de taal waarmee je met een relationele database praat. Je beschrijft wat je wilt hebben, de database bedenkt zelf hoe hij het vindt.

Vergelijk het met bestellen in een restaurant: je zegt "een pizza margherita", niet hoe de kok het deeg moet kneden. Zo'n taal heet declaratief. Daarom lees je SQL bijna als een Engelse zin.

SELECT gebruikersnaam FROM gebruiker WHERE land = 'België';

"Geef de gebruikersnaam uit de tabel gebruiker, waar het land België is."

Twee soorten opdrachten

SoortDoelOpdrachtenHoofdstuk
DDL · Data DefinitionDe structuur bouwen: databases en tabellenCREATE, ALTER, DROP5, 7
DML · Data ManipulationDe gegevens zelf opvragen en wijzigenSELECT, INSERT, UPDATE, DELETE6 t/m 11

Spelregels

  • Elke opdracht eindigt met een puntkomma ;. Vergeet je die in de terminal, dan verandert de prompt in ->: MySQL wacht op meer.
  • Sleutelwoorden schrijf je in hoofdletters (SELECT, FROM). Dat is niet verplicht, maar wel afgesproken: het leest makkelijker.
  • Tekst en datums staan tussen enkele aanhalingstekens: 'België', '2026-10-09'. Getallen niet: 20000.
  • Namen van tabellen en kolommen hebben geen spaties. Gebruik een underscore: gebruiker_id.
  • Commentaar begint met -- en wordt overgeslagen.

Vaste volgorde

De onderdelen van een SELECT hebben een vaste volgorde. Je hoeft niet alles te gebruiken, maar wat je gebruikt, staat op deze plek.

SELECT   kolommen          -- wat wil je zien?
FROM     tabel             -- waar staat het?
WHERE    voorwaarde        -- welke rijen?
GROUP BY kolom             -- groepen maken (hoofdstuk 11)
ORDER BY kolom             -- sorteren
LIMIT    aantal;           -- hoeveel rijen?

Oefenen

Zoek de fout in elke opdracht.

  1. SELECT * FROM gebruiker WHERE land = België;

    Antwoord

    Tekst moet tussen aanhalingstekens: 'België'.

  2. SELECT * FROM highscore ORDER BY score DESC WHERE score > 1000;

    Antwoord

    De volgorde klopt niet: WHERE komt vóór ORDER BY.

  3. SELECT gebruikers naam FROM gebruiker;

    Antwoord

    Een kolomnaam heeft geen spatie. Het moet gebruikersnaam zijn.

  4. Is CREATE TABLE DDL of DML? En UPDATE?

    Antwoord

    CREATE TABLE is DDL: het bouwt structuur. UPDATE is DML: het wijzigt gegevens.

06

Gegevens opvragen met SELECT

Met SELECT vraag je gegevens op. Het verandert niets aan de database, dus experimenteer gerust.

USE game;

-- alles uit een tabel
SELECT * FROM gebruiker;

-- alleen bepaalde kolommen
SELECT gebruikersnaam, land FROM gebruiker;

-- alleen bepaalde rijen
SELECT * FROM highscore WHERE level >= 10;

-- sorteren (DESC = van hoog naar laag) en beperken
SELECT * FROM highscore ORDER BY score DESC LIMIT 3;

Voorwaarden in WHERE

TekenBetekenisVoorbeeld
= <>gelijk aan, niet gelijk aanland = 'Duitsland'
> < >= <=groter, kleinerscore > 20000
AND ORbeide waar, één van beide waarland = 'België' AND level > 5
LIKEtekstpatroon; % is "wat dan ook"gebruikersnaam LIKE 'P%'
BETWEENtussen twee waardenscore BETWEEN 5000 AND 10000
IS NULLveld is leegland IS NULL

Tellen en rekenen

Functies als COUNT, MAX, MIN, AVG en SUM vatten veel rijen samen in één getal. Met AS geef je de uitkomst een leesbare naam.

SELECT COUNT(*) AS aantal_potjes, MAX(score) AS beste_score FROM highscore;

07

Tabellen maken met CREATE, rijen toevoegen met INSERT

Bij het maken van een tabel leg je per kolom vast wat erin mag: het datatype en de regels. De database houdt zich daar daarna streng aan.

Datatypen

TypeVoorVoorbeeld
INThele getallenscore, level, id's
DECIMAL(5,2)exacte kommagetallen: 5 cijfers, waarvan 2 achter de kommaprijzen, zoals 8.15
VARCHAR(n)tekst van maximaal n tekensgebruikersnaam, e-mail
TEXTlange teksteen beschrijving, een bericht
DATEdatum (jjjj-mm-dd)'2026-01-12'
DATETIMEdatum en tijd'2026-09-01 19:12:00'
BOOLEANwaar of onwaaris_beheerder

Gebruik voor geld nooit FLOAT: dat type rekent met afrondingsfouten. DECIMAL is exact.

Regels voor een kolom

RegelBetekenis
PRIMARY KEYIdentificeert elke rij. Uniek en nooit leeg. Elke tabel heeft er één.
AUTO_INCREMENTMySQL kiest zelf het volgende nummer.
NOT NULLMag niet leeg blijven.
UNIQUEMag maar één keer voorkomen in de kolom.
DEFAULT 10Waarde als je zelf niets invult.
FOREIGN KEY … REFERENCESVerwijst naar de primary key van een andere tabel. De database controleert of die rij bestaat.

Primary key en foreign key

In de tabel highscore is highscore_id de primary key: elk potje heeft een eigen nummer. De kolom gebruiker_id is een foreign key: hij wijst naar gebruiker.gebruiker_id. Daardoor kun je geen score opslaan voor een speler die niet bestaat.

Rijen toevoegen met INSERT

INSERT INTO gebruiker (gebruiker_id, gebruikersnaam, email, land, aangemaakt_op)

-- highscore_id laat je weg: AUTO_INCREMENT vult het in. NOW() is de huidige tijd.
INSERT INTO highscore (gebruiker_id, score, level, gespeeld_op)
VALUES (12, 4200, 2, NOW());

Rijen verwijderen met DELETE

DELETE haalt rijen weg. Er is geen prullenbak en geen ongedaan maken.

DELETE FROM highscore WHERE highscore_id = 26;
Vergeet nooit de WHERE

DELETE FROM highscore; zonder WHERE wist álle highscores. Maak er een gewoonte van: schrijf eerst een SELECT met dezelfde WHERE. Zie je precies de rijen die weg moeten? Vervang dan SELECT * door DELETE.

De foreign key beschermt je data. Heeft een gebruiker nog highscores, dan weigert MySQL die gebruiker te verwijderen: die scores zouden anders naar niemand wijzen. Verwijder eerst de highscores, of kies bij het maken van de tabel voor ON DELETE CASCADE. Dan gaan de highscores automatisch mee.

MySQL Workbench: Error 1175?

Workbench staat standaard in "safe update mode" en weigert een DELETE of UPDATE die niet op de primary key filtert. Filter op het id, of zet het tijdelijk uit met SET SQL_SAFE_UPDATES = 0;

Op zoek naar patronen

Een database is meer dan een archief. Met GROUP BY zie je patronen die op geen enkele losse kassabon staan.

GROUP BY maakt groepjes van rijen met dezelfde waarde, en een functie als COUNT of SUM vat elk groepje samen. Alles wat in je SELECT staat en geen telling is, zet je ook in de GROUP BY.

-- aantal klanten per woonplaats, grootste eerst
SELECT woonplaats, COUNT(*) AS klanten
FROM klanten
GROUP BY woonplaats
ORDER BY klanten DESC;

Zet aan het begin van je sessie de taal voor dag- en maandnamen op Nederlands. Dan krijg je "dinsdag" in plaats van "Tuesday":

SET lc_time_names = 'nl_NL';

Onderzoeken

Probeer eerst zelf een query te bedenken. Bekijk daarna het antwoord en vooral de uitleg: wat zegt dit over de winkel?

  1. Op welke dag van de week is het het drukst? En wanneer het rustigst?

    Antwoord
    SET lc_time_names = 'nl_NL';
SELECT DAYNAME(datum) AS dag, COUNT(*) AS transacties
FROM transactie
GROUP BY DAYNAME(datum)
ORDER BY transacties DESC;
    dinsdag 2245 · zaterdag 2228 · … · maandag 1332

    Dinsdag is bijna net zo druk als zaterdag, en maandag het rustigst. Handig voor het rooster van medewerkers.

  2. Hoe ontwikkelt de omzet zich per maand?

    Antwoord
    SELECT MONTH(t.datum) AS maand, SUM(tp.aantal * p.verkoopprijs) AS omzet
FROM transactie t
JOIN trans_prod tp ON tp.trans_id = t.trans_id
JOIN producten p   ON p.product_id = tp.prod_id
GROUP BY MONTH(t.datum)
ORDER BY maand;
    januari € 6.570,32 (hoogst) · februari € 6.035,51 (laagst)

    De omzet is opvallend stabiel: elke maand tussen de € 6.000 en € 6.600. Februari is laag, maar heeft ook maar 28 dagen.

  3. Hoe groot is een gemiddelde bon, in producten en in euro's?

    Antwoord
    SELECT ROUND(AVG(stuks), 2) AS producten, ROUND(AVG(bedrag), 2) AS euro
FROM (
    SELECT tp.trans_id, SUM(tp.aantal) AS stuks, SUM(tp.aantal * p.verkoopprijs) AS bedrag
    FROM trans_prod tp
    JOIN producten p ON p.product_id = tp.prod_id
    GROUP BY tp.trans_id
) AS bonnen;
    1,27 producten · € 3,02

    Dit is geen weekboodschap: mensen halen iets kleins voor onderweg. Dat past bij een to-go-winkel op een station en in het centrum. De query gebruikt een subquery: eerst één rij per bon, daarna het gemiddelde daarvan.

  4. Waar doen klanten uit Goirle en uit Nuenen hun boodschappen?

    Antwoord
    SELECT k.woonplaats, l.plaats AS winkel, COUNT(*) AS transacties
FROM transactie t
JOIN klanten k ON k.klant_id = t.klant_id
JOIN locatie l ON l.loc_id = t.loc_id
WHERE k.woonplaats IN ('Goirle', 'Nuenen')
GROUP BY k.woonplaats, l.plaats;
    Goirle → Tilburg 656, Eindhoven 1 · Nuenen → Eindhoven 607

    Klanten zijn honkvast: ze gaan naar de winkel bij hen in de buurt. Goirle ligt naast Tilburg, Nuenen naast Eindhoven.

  5. Welke productcategorie levert de meeste winst op (verkoopprijs min inkoopprijs, keer het aantal)?

    Antwoord
    SELECT p.categorie, SUM(tp.aantal * (p.verkoopprijs - p.inkoopprijs)) AS winst
FROM trans_prod tp
JOIN producten p ON p.product_id = tp.prod_id
GROUP BY p.categorie
ORDER BY winst DESC
LIMIT 3;
    Broodbeleg vers € 2.371,21 · Zuivel € 2.068,04 · Frisdrank € 1.983,84

  6. Zijn er producten die nooit verkocht zijn?

    Antwoord
    SELECT p.naam
FROM producten p
LEFT JOIN trans_prod tp ON tp.prod_id = p.product_id
WHERE tp.prod_id IS NULL;
    Geen rijen: elk product is minstens één keer verkocht

    Een LEFT JOIN houdt álle producten, ook die zonder bonregel. Bij die producten is tp.prod_id leeg. Ook "geen resultaat" is een antwoord.

  7. Een collega zegt: "50-plussers kopen veel meer frisdrank dan jongeren." Klopt dat?

    Antwoord
    SELECT CASE
         WHEN TIMESTAMPDIFF(YEAR, k.geb_datum, '2023-06-30') < 30 THEN 'onder 30'
         WHEN TIMESTAMPDIFF(YEAR, k.geb_datum, '2023-06-30') < 50 THEN '30-49'
         ELSE '50+'
       END AS leeftijd,
       COUNT(DISTINCT k.klant_id) AS klanten,
       SUM(CASE WHEN p.categorie = 'Frisdrank' THEN tp.aantal ELSE 0 END) AS frisdrank
FROM klanten k
JOIN transactie t  ON t.klant_id = k.klant_id
JOIN trans_prod tp ON tp.trans_id = t.trans_id
JOIN producten p   ON p.product_id = tp.prod_id
GROUP BY leeftijd;
    50+: 150 klanten, 886 frisdrank · 30-49: 96 klanten, 565 · onder 30: 36 klanten, 233

    In totalen lijkt het te kloppen: 886 tegen 233. Maar er zijn ook veel meer 50-plussers. Deel je door het aantal klanten, dan koopt elke groep ongeveer evenveel: 5,9, 5,9 en 6,5 per klant. Jongeren kopen per persoon zelfs iets meer. Vergelijk groepen dus altijd per klant, niet in totalen.

Je database koppelen aan je app

Een database wordt pas echt nuttig als je eigen app hem gebruikt. Je app stuurt dezelfde SQL die je in de vorige hoofdstukken schreef, en krijgt de rijen terug als gewone objecten of lijsten.

Het voorbeeld is een leaderboard voor Pixel Runner. De app toont de top 10 uit de database game en kan een nieuwe score opslaan. Je hebt dus de database uit hoofdstuk 5 nodig, en je container moet draaien.

Altijd met parameters

Plak nooit invoer van een gebruiker rechtstreeks in je SQL-tekst. Typt iemand als naam x'; DROP TABLE highscore; --, dan voert de database dat gewoon uit. Dit heet SQL-injectie. Gebruik daarom parameters: plekken in je SQL die de connector veilig invult. In C# zijn dat @naam, in Python %s.

    using MySqlConnector;

namespace PixelRunner;

public class Database
{
    // Dezelfde gegevens als in je SQL-programma
    private const string ConnectionString =
        "Server=localhost;Port=3306;User ID=root;Password=welkom;Database=game";

    public List<Highscore> HaalTop10()
    {
        var lijst = new List<Highscore>();

        using var verbinding = new MySqlConnection(ConnectionString);
        verbinding.Open();

        using var opdracht = new MySqlCommand(@"
            SELECT g.gebruikersnaam, h.score, h.level
            FROM highscore h
            JOIN gebruiker g ON g.gebruiker_id = h.gebruiker_id
            ORDER BY h.score DESC
            LIMIT 10", verbinding);

        using var lezer = opdracht.ExecuteReader();
        while (lezer.Read())
        {
            lijst.Add(new Highscore(lezer.GetString(0), lezer.GetInt32(1), lezer.GetInt32(2)));
        }
        return lijst;
    }

    public void VoegScoreToe(int gebruikerId, int score, int level)
    {
        using var verbinding = new MySqlConnection(ConnectionString);
        verbinding.Open();

        // @id, @score en @level zijn parameters: MySqlConnector vult ze veilig in
        using var opdracht = new MySqlCommand(@"
            INSERT INTO highscore (gebruiker_id, score, level, gespeeld_op)
            VALUES (@id, @score, @level, NOW())", verbinding);
        opdracht.Parameters.AddWithValue("@id", gebruikerId);
        opdracht.Parameters.AddWithValue("@score", score);
        opdracht.Parameters.AddWithValue("@level", level);
        opdracht.ExecuteNonQuery();
    }
}

def toon_top10():
    cursor.execute("""
        SELECT g.gebruikersnaam, h.score, h.level
        FROM highscore h
        JOIN gebruiker g ON g.gebruiker_id = h.gebruiker_id
        ORDER BY h.score DESC
        LIMIT 10
    """)
    print("\n  #  Speler           Score  Level")
    for nr, (naam, score, level) in enumerate(cursor.fetchall(), start=1):
        print(f"{nr:>3}  {naam:<15} {score:>6}  {level:>5}")


def voeg_score_toe(gebruiker_id, score, level):
    # %s zijn plekken voor waarden: de connector vult ze veilig in
    cursor.execute(
        "INSERT INTO highscore (gebruiker_id, score, level, gespeeld_op) "
        "VALUES (%s, %s, %s, NOW())",
        (gebruiker_id, score, level),
    )
    db.commit()  # pas na commit staat de wijziging echt in de database
    print(f"Score {score} opgeslagen.")

Vergeet commit niet

Python bundelt wijzigingen tot je db.commit() aanroept. Zonder commit lijkt je INSERT gelukt, maar staat de score niet echt in de database. MySqlConnector in C# slaat elke opdracht direct op.

Alleen om te oefenen

Een wachtwoord in je code en inloggen als root zijn prima op je eigen laptop. In een echte app maak je een aparte databasegebruiker met alleen de rechten die de app nodig heeft, en staat het wachtwoord niet in de code.

Oefenen

  1. Laat je app alleen de scores van één land zien. Welke regel in je SQL pas je aan?

    Antwoord

    Voeg een WHERE toe vóór ORDER BY, met een parameter voor het land: WHERE g.land = @land in C#, WHERE g.land = %s in Python. Geef het land mee zoals bij de INSERT.

  2. Waarom schrijf je niet "... VALUES (" + score + ")" in je code?

    Antwoord

    Dan wordt invoer van de gebruiker deel van je SQL. Met slimme invoer kan iemand dan eigen SQL laten uitvoeren (SQL-injectie). Parameters houden invoer en SQL gescheiden.

  3. Breid de app uit: toon naast de top 10 ook het aantal gespeelde potjes per speler.

    Tip

    Schrijf en test de query eerst in je SQL-programma. Gebruik COUNT(*) en GROUP BY g.gebruikersnaam, zoals in hoofdstuk 11. Werkt hij daar, zet hem dan in je app.
